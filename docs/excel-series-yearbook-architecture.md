# 엑셀 시계열 원장 기반 연보 생성

## 결론

엑셀을 곧바로 한 권의 연보로 해석하면 안 된다. 다음 세 계층을 분리한다.

1. **시계열 원장**: 전체 이력과 당해연도 증분을 수정 이력이 남도록 저장
2. **연보 템플릿·레시피**: 원장의 어느 기간·행·열을 어떤 연보 표에 배치할지 버전 관리
3. **연보 스냅샷**: 특정 연도에 실제로 게시·검수할 표를 불변 데이터로 생성

생성된 스냅샷은 기존 `ParsedReport → annual_reports/stat_tables/cells →
validation_profiles → validation engine` 경로에 넣는다. 따라서 계산·언어 검수와
화면 표시를 새로 만들지 않고 기존 검수 결과 계약을 그대로 유지한다.

원장과 스냅샷을 분리하면 2010년 이후 전체 데이터는 DB에 유지하면서도 2026
연보에는 2016~2025처럼 승인된 구간만 표시할 수 있다.

## 현재 프로젝트에서 확인한 내용

- 기준 DB에는 2025 연보 359개 물리 표, 2026 연보 363개 물리 표가 있다.
- 2025·2026 대표 표의 검수 결과와 하이라이트는
  `tests/fixtures/validation_baseline.json`으로 고정되어 있다.
- 기존 Excel 파서는 완성된 연보 한 권을 읽는 파서다. 원장형 Excel을 같은 파서에
  넣으면 표 번호, 영문, 주석, 출처, 연보 표시 범위를 복원할 수 없다.
- 현재 프로파일 구조 서명은 연도 행 라벨도 포함한다. 연도 창만 한 칸 이동해도 새
  구조로 오인할 수 있어, 별도의 호환 구조 서명을 추가했다.

로컬에서 확인한 원천 후보는 다음 특성이 있다.

- 통계 시스템 내보내기 3종은 `표정보`, `표항목`, `표데이터`로 나뉜다.
- 표정보는 296개 표 ID, 표데이터는 294개 표 ID를 포함하지만 표항목은 50개 표
  ID만 포함한다. 현재 세 파일만으로 294개 표의 모든 헤더 계층을 완전히 복원할
  수 없다.
- 표별 `.xls`는 기준년도와 다단 헤더를 포함해 시계열 원장으로 사용할 수 있다.
- `연도별 승강기 안전교육`, `지방공무원 육아휴직`은 원천 Excel만으로 2026
  확정 표의 데이터 셀을 동일하게 재생성했다.
- `지역별 민방위대 편성`은 같은 2025 기준년도 원천과 확정 HWPX 값이 다르다.
  원천 수정 시점 또는 기준시점 정의를 확인해야 한다.
- 시·군·구 목록 같은 텍스트 값에는 원천 Excel에 영문이 없지만 HWPX에는 영문이
  있다. 번역 원천이나 승인 번역 레이어 없이 “완벽히 동일”하게 복원할 수 없다.

따라서 2025·2026 재현 검사는 단순 성공/실패가 아니라 다음처럼 결과를 나눈다.

- `exact`: 모든 셀과 메타정보가 기준 연보와 동일
- `data_mismatch`: 같은 키의 원천값과 확정 연보값이 다름
- `missing_source`: 영문·주석·출처·항목 계층 등 입력에 없는 정보
- `mapping_required`: 피벗, 표 분할/병합 또는 명칭 변경으로 명시적 레시피 필요

`exact`가 아닌 표를 자동 게시 상태로 만들면 안 된다.

## 데이터 모델

### 원장 적재

| 테이블 | 역할 |
| --- | --- |
| `series_import_batches` | 파일 해시, 전체/증분 구분, 대상 연도, 처리 결과 |
| `statistical_datasets` | 원천 통계의 안정적인 식별자와 제목 |
| `statistical_dataset_versions` | 헤더 계층, 기준연도 열, 차원 열, 구조 서명 |
| `statistical_observations` | 기준연도+차원별 값과 원본 행 위치, 적재 배치 |

관측치는 덮어쓰지 않는다. 동일한 기준연도·차원이 다시 들어오면 새 배치의 관측치를
최신값으로 읽되 이전 배치도 남겨 정정 이력을 추적한다. 동일 파일 재업로드는 파일
해시로 재사용한다.

### 연보 표 레시피

`yearbook_table_recipes`는 표 번호별로 다음 정보를 갖는다.

- 적용 시작·종료 연보 연도
- 연결된 원천 데이터셋
- 변환기 종류
- 기간 창, 행/열 키 대응, 0/대시·소수·천 단위 표시 정책
- 기준이 된 확정 연보와 표
- 초안/승인 상태

기본 변환기는 다음과 같다.

- `copy`: 당해연도 변경이 없는 표를 이전 확정 스냅샷에서 복사
- `period_rows`: 연도가 행인 표에서 마지막 N개 기간 선택
- `current_period_rows`: 대상 연도 한 개를 선택하고 지역·구분 행에 반영
- `period_columns`: 연도를 열로 피벗하고 마지막 N개 기간 선택
- `split` / `merge`: 하나의 원천 통계를 여러 연보 표로 나누거나 여러 원천을 결합
- `custom`: 승인된 명시 매핑. 코드가 아니라 가능한 한 JSON 설정으로 관리

현재 구현은 오류 가능성이 낮은 `period_rows`, `current_period_rows`를 자동
판별한다. 피벗·분할·병합과 구조 변경은 자동 추측하지 않고 레시피 승인 대상으로
남긴다.

현재 원장 적재 CLI는 다음처럼 사용할 수 있다.

```bash
PYTHONPATH=backend .venv/bin/python -m app.yearbook_data.import_series \
  전체시계열.xlsx --kind full

PYTHONPATH=backend .venv/bin/python -m app.yearbook_data.import_series \
  2027신규분.xlsx --kind incremental --target-year 2027
```

이 명령은 원장만 갱신하며 `annual_reports`를 게시하거나 검수를 자동 실행하지
않는다. 전수 재현 gate와 레시피 승인 API가 연결되기 전까지의 안전장치다.

## 연도별 처리 흐름

1. Excel 파일을 원장 staging에 파싱한다.
2. 파일 해시, 헤더 구조, 기준연도·차원 중복을 검증한다.
3. 전체 적재는 원장을 초기 구성하고 증분 적재는 새 배치로 관측치를 추가한다.
4. 대상 연도의 활성 레시피와 이전 확정 연보 manifest를 읽는다.
5. 표마다 `동일`, `데이터만 변경`, `구조 변경`, `신규`, `삭제`를 판정한다.
6. 자동 처리 가능한 표를 staging 연보로 생성한다.
7. 2025·2026 기준 연보와 같은 방식으로 셀·메타정보·표 순서·검수 결과를 비교한다.
8. 모든 필수 표가 `exact` 또는 승인된 차이일 때만 `annual_reports`에 게시한다.
9. 기존 프로파일을 구조 호환성에 따라 승계하고 같은 검수 엔진을 실행한다.

생성과 게시를 분리해야 일부 표만 잘못 생성된 연보가 화면에 노출되지 않는다.

## 변경 유형 처리

### 1. 형식 동일, 1년 데이터 추가

- 원장에 새 기간을 추가한다.
- 레시피의 기간 창만큼 잘라 이전 표 레이아웃에 넣는다.
- 표 크기와 좌표가 같으면 검수 프로파일을 그대로 승계한다.
- 이번 구현부터 4자리 연도 라벨만 이동한 구조는 호환 구조로 판정한다.

### 2. 통계 내용 또는 형식 일부 변경

- 헤더·차원·행 키·데이터형의 구조 서명 차이를 기록한다.
- 단순 명칭 변경은 alias 매핑을 승인한다.
- 행/열 추가, 피벗, 분할·병합은 새 레시피 revision을 만든다.
- 새 구조에서는 기존 프로파일을 무조건 실행하지 않는다. 좌표 유효성을 검사한 뒤
  승계하거나 새 프로파일을 생성하고 `needs_review`로 둔다.

### 3. 통계 삭제 또는 신규 추가

- 삭제는 “이번 파일에 없음”만으로 판단하지 않는다. 부분 증분 파일일 수 있으므로
  연보 manifest 또는 명시적 종료 연도가 필요하다.
- 신규 통계는 표 번호, 국·영문 제목, 단위, 기준일, 출처, 표 순서가 있어야 기본
  템플릿을 만들 수 있다.
- 해당 정보가 없으면 기본 한국어 표를 staging에 만들 수는 있지만 확정 연보와
  동일하다고 간주하지 않고 승인 대상으로 둔다.

## 완전 재현을 위한 입력 계약

원천값 외에 다음 정보가 있어야 HWPX 기준 연보를 완전히 재현할 수 있다.

- 안정적인 원천 통계 ID와 연보 표 번호의 대응
- 다단 항목 전체(현재 표항목 내보내기의 누락 해소)
- 표별 표시 기간 또는 기간 창
- 표의 행/열/피벗/분할 규칙
- 국·영문 제목·헤더·텍스트 값
- 단위, 기준일, 주석, 출처, 분야, 표 순서
- 신규·삭제·명칭 변경의 명시적 manifest
- 0, 빈값, 대시, 소수점, 천 단위 표시 규칙

이 중 원천 Excel에 없는 값은 2026 확정 연보 템플릿에서 승계할 수 있다. 하지만
신규 통계와 변경된 텍스트의 영문은 별도 입력 또는 담당자 승인이 필요하다.

## 구현 상태와 다음 단계

완료:

- `.xlsx`와 구형 `.xls` 다단 헤더 시계열 파서
- 전체/증분 배치와 수정 이력을 보존하는 원장 DB
- 연도 행·당해연도 차원 행 표의 레이아웃 유지 변환
- 신규·삭제 행을 자동 게시하지 않는 구조 변경 감지
- 연도 창 이동 시 검수 프로파일 호환 승계
- 단위 테스트와 실제 2026 표 일부의 셀 단위 재현 확인

다음 구현 순서:

1. 전체 데이터 Excel의 누락 없는 실제 파일을 기준으로 원천 ID와 2026 표 번호를
   매칭하고 재현율 리포트 생성
2. `period_columns`, `split`, `merge` 레시피와 recipe 승인 API 구현
3. 2026 전체 363개 표를 Excel에서 staging 재생성하고 기준 DB와 전수 비교
4. 불일치 원인을 데이터/번역/메타정보/매핑으로 분류해 해소
5. 전수 재현 통과 뒤 Excel 원장 업로드를 운영 UI와 자동 검수 작업에 연결

현재 단계에서 기존 `연보 업로드` 버튼을 원장 업로드로 바로 바꾸지 않은 이유는,
불완전한 표항목·번역 데이터를 완성 연보로 오인해 운영 DB에 게시하는 것을 막기
위해서다.
