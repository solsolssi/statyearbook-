# 2026 증분 초안 실제 연보 대조

## 대조 범위

- 기준 연보: 보고서 101, 2025 행정안전통계연보
- 증분 초안: 보고서 106
- 정답 대조용 완성 연보: 보고서 108, 실제 업로드된 2026 연보
- 증분 파일: 표정보 296건, 값이 있는 데이터셋 294건, 표항목과 값이 모두 있어 실제 자동 갱신을 시도할 수 있는 데이터셋 50건

완성 2026 연보는 증분 셀 값을 만드는 입력으로 복사하지 않았다. 표 번호·표 순서와 기간창 정책을 학습하고, 생성 결과가 실제 완성본과 같은지를 사후 대조하는 용도로만 사용했다. 전체 통계 원장은 생성·파싱·검수 흐름에 사용하지 않는다.

## 결론

기존 자동 판정은 50건 중 40건을 연결 완료로 보았지만, 실제 2026 연보와 표 크기 및 좌표별 표시값을 대조하자 정확히 일치한 것은 12건이었다. 나머지 28건은 잘못된 자동 통과였으므로 현재 초안에서 `확인 필요`로 되돌렸다.

| 구분 | 건수 | 현재 처리 |
|---|---:|---|
| 실제 2026과 일치 | 12 | 자동 반영 유지 |
| 기존 통과였으나 실제 구조/값 불일치 | 28 | 확인 필요로 격리 |
| 연결은 찾았으나 행 항목 불일치 | 1 | 확인 필요 유지 |

## 기존 오통과 28건의 유형

- 구조 불일치 13건: 증분 항목을 그대로 열로 재작성했지만 실제 연보는 일부 항목을 합치거나 제외하고, 행도 추가·삭제했다.
- 값 불일치 15건: 표 크기는 같아도 행/열 의미 매핑, 합계·비율 파생값, 빈 값 처리 또는 항목 순서가 실제 연보와 달랐다.

대표적으로 `3-1-3-2 연도별 정보시스템`은 같은 크기여도 34개 좌표가 달랐고, `4-1-6-2 연도별 조례･규칙 보유`는 증분에 직접 없는 합계 셀 1개를 재산출해야 했다. 크기만 같은 표를 통과시키면 안 되는 이유다.

## 구현한 증분 갱신 유형

증분 갱신은 두 종류가 아니라 다음 유형으로 구분한다.

1. 연도 행 추가/기존 목표연도 행 갱신
2. 같은 연도가 여러 세부 행으로 구성된 묶음 행 추가
3. 연도 열 추가/기존 목표연도 열 갱신
4. 고정 기간창 이동(가장 오래된 연도 제거)과 전체 이력 유지(기존 연도 보존)를 통계별로 분리
5. 행 라벨·열 헤더를 기준으로 한 스냅샷 값 갱신
6. 증분의 계층형 항목에 따른 병합 헤더·상위 헤더 재구성
7. 전체 스냅샷 교체
8. 하나의 M키가 여러 물리 표를 갱신하는 분리 통계
9. 신규 통계, 삭제 통계, 제목·번호 변경
10. 증분에 직접 없는 합계·비율·증감률 파생값 재계산

현재 1~7의 구조 판정과 안전 격리, 신규 생성/제외/수동 M키 연결 UI가 구현되어 있다. 8~10처럼 자료별 명시 규칙이 필요한 경우에는 임의 통과하지 않고 확인 필요로 남긴다.

## 추가한 안전장치

- 표 번호와 이름이 바뀌어도 증분에 목표 표 번호가 있으면 이를 우선 반영한다.
- 연도 축이 행인지 열인지 자동 구분한다.
- 기간창을 무조건 밀어내지 않고 통계별 `rolling_window`와 `append_history`를 저장한다.
- 행/열 구조가 같아도 좌표별 표시값이 완성본과 다르면 자동 통과를 취소한다.
- 실제 완성 연보 대조 실패 사유를 `REFERENCE_STRUCTURE_MISMATCH`와 `REFERENCE_VALUE_MISMATCH`로 저장한다.
- 확인 필요 상태에서는 연보 확정을 차단한다.
- 비교 시 한/영 병기, 쉼표, 퍼센트 기호, 빈 값과 대시는 표시 차이로 정규화하지만 숫자와 텍스트 의미 차이는 그대로 실패 처리한다.
